# DRLEFLUSH -- copro firmware flush for the LeafEval GO-reset gap (2026-10-04, branch claude/fw-leflush)
# RTL NES_MiSTer-drmario claude/dist-leaf 3b164c7 (DIST60: -DDRHSV -DDRLEV_SQREG -DDRLEV_WRREG -DDRLEV_VNPF -DDRDIST),
# unchanged. Firmware V11 = V1 a1ef31c8 (1488e158 + DRTUCKREACH + DRTUCKLIVE + DRROOTORD, mask 19/8) + DRLEFLUSH
#   build_fw.py 540 OUT 1 1 1 1 1 1 19 8 1   -> c51d2e21af8ed98ad929a2254befb2b5
#   (DIST60 1488e158 + DRLEFLUSH: build_fw.py 540 OUT 1 1 1 0 0 0 19 8 1 -> 25bdb23a, used as the 1488 positive arm)
# Problem (copro-pipeline lane, experiments/abortstale/COSIM.txt section 6, PR #33): a GO preempting a search resets
# LeafEval's st/done/modes only; after a reset MID LeafEval command the next search's first BASE ran 241 clocks instead
# of 1,590 and latched base_holes 0x17 vs 0x16; preempt-at-50 % changed intermediate publishes on 3/115 G2 pairs (1488).

## 0. verdict
- Exactly ONE of the 180 engine registers that survive the GO reset can carry stale state into a result: dphase. Static
  enumeration (coverage-checked against the RTL), and measured: poisoning ALL 179 others with random values changes 0 of
  335 searches (flag off), while dphase := 1 or 2 alone changes 77/116 (2 publish-sequence changes).
- DRLEFLUSH (stub CMD 7 with an illegal landing, +18 bytes, +22 clocks = 1.5e-5 frame per search) neutralises it: with
  every register randomised (+ the work RAM on G2) the flushed search is bit-identical to a fresh run on 335 + 116 + 116
  searches; dphase := 1 / 2 -> 232/232 exact.
- Real preemptions: adversarial pairs 345/345 exact (q 0.25 / 0.5 / 0.75) and 115/115 on 1488+flush (lane without the
  flush: 1488 3 DECISION + 8 mesen-same, V1 12 mesen-same); chained abort-cart co-sim G2/G3/G4 335/335 exact whole-game
  (27 preempted searches) + 107/107 windows.
- No preemption: finals, tucks and publish values identical to V1 on all 335 co-sim boards (on 9 a publish is seen one
  poll later, 3,264 clocks = 0.0023 f, same Mesen frame; 1488+flush vs 1488e158: 3/116 likewise) and on 264 py65 boards; Mesen replay on the abort cart == A+V1 exactly
  (G2 113/1/21.5, G3 85/0, G4 133/0, 0 landing and 0 GO-frame differences).
- rbf seed 21: copro +0.364 ns, pll_hdmi -0.058 ns (bar -0.062), ALMs 37737; 16/16 bijection; md5 b64d8ea9.

## 2. the flush
Reset stub ($BF80), DRLEFLUSH=1, +18 bytes (the only bytes that differ from the flag-off image):
    SEI / CLD
    LDA #2 / STA $70E0   ; a_o4 = 2: horizontal ...
    LDA #7 / STA $70E1   ; a_col = 7: ... at column 7 -- an ILLEGAL landing by construction (S_FO1: a_o4[1] && a_col == 7)
    STA $70F4            ; CMD 7. Its S_IDLE entry writes dphase := 0 (and zeroes legal / rv / imm / markb / chain /
                         ; od_* nd_* dd_* / dv_fallback); S_FO1 walks column 7 (<= 17 clocks) and exits with done = 1,
                         ; legal = 0, without placing, resolving or touching CUR, the slots or the CMD 6 latches
    LDX #$FF / TXS / LDX #15 / cp2: LDA $B030,X / STA $09C0,X / DEX / BPL cp2     ; unchanged pill-table copy (~229 clk)
    lfp: LDA $70F8 / BEQ lfp                                                      ; DONE long since: exits on the 1st read
    ...                  ; unchanged (tuck descriptor defaults, JSR search, JSR tuck, publish, DONE)
Why CMD 7 and not a dummy evaluation: CMD 7's ENTRY is the only writer of dphase outside the delta path itself; a dummy
LEAF / NODE / BASE READS dphase (S_VSPAN_D) and would itself take the stale detour. Unconditional (the firmware cannot
tell a preempted predecessor: GO clears DONE): it costs less than a conditional test would.
Cost (measured): +22 copro clocks per search, constant (Verilator: first BASE issued at clk 137,232 vs 137,210 for V1
p89, 163,293 vs 163,271 for 1488e158 p28, identical in the preempted and the fresh run; py65: +22 cycles, +7
instructions on all 264 boards). At 85.909 MHz = 0.256 us = 1.54e-5 frame (1 frame = 1,429,464 clocks):
~4e-5 pp tap-out at +2.8 pp per frame. No other byte of the search, tuck, reach or dist images moves.
