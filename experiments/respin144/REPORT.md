## DEFECT 1 — video PLL (mechanism INDEPENDENTLY CONFIRMED against the fit report)

corevideo's claim: Quartus-23.1 builds map pll_hdmi outclk_0 to a physical C-counter
other than C0; Main's runtime C-divider write misses; divider stuck at compile C=3.

My verification (theta400dblcanon-seed13 archive, NES.fit.rpt):
- fit rpt line 13901: pll_hdmi counter[0].output_counter "Output Clock Location":
  **PLLOUTPUTCOUNTER_X0_Y7_N1** — physical counter 1, NOT 0.
- Census: EVERY PLL in the design has its divclk at **N1** (X0_Y60_N1, X0_Y7_N1,
  X89_Y0_N1, X89_Y5_N1, X89_Y7_N1) — the Q23 fitter systematically avoids N0,
  so this is a flow property, not a one-off placement.
- Reconfig addressing is PHYSICAL: sys/pll_cfg/pll_cfg_hdmi.v C_CNT_0_DIV_ADDR=5'h00
  base + counter index; the only fitter-reconfigged LUT is the fpll_0/1 select
  (lcell_fpll_0_1), NOT a counter remap. So a C-counter-0 write goes to physical C0
  = an UNUSED counter; the live divider on C1 keeps its compile value.
- Compile default: pll_hdmi_0002.v = one clock @ 148.5 MHz (VCO 445.5 / C=3) —
  exactly the stuck 148.5 corevideo measured on the ADV7513 CTS.
- Control side (emu pll): NES.sv's PAL/NTSC reconfig writes only addrs 0/7/2
  (mode/K-frac/start), NO C counters — which is why the core plays at correct
  speed despite the same N1 placement. Only pll_hdmi is affected.

FIX (option b): pin the counter to physical C0 in NES.qsf:
  set_location_assignment PLLOUTPUTCOUNTER_X0_Y7_N0 -to "pll_hdmi:pll_hdmi|pll_hdmi_0002:pll_hdmi_inst|altera_pll:altera_pll_i|altera_cyclonev_pll:cyclonev_pll|counter[0].output_counter"
N0 at X0_Y7 is unoccupied (pll_hdmi has exactly 1 outclk). Post-fit content proof:
fit rpt Output Clock Location must read ...N0 AND the Ignored-Assignments section
must NOT list the location assignment (an ignored pin reads as success otherwise).
End proof is the on-box ADV7513 gate (720p→CTS 74250 AND 1080p→CTS 148500).
